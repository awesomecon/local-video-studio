# MiniMax H3 local worker

H3 is integrated as a local HTTP worker rather than imported into the FastAPI process. This preserves
the application's working PyTorch environment and lets H3 use its own compatible dependencies.

Supported request concepts include FL2VA and Ref2VA workflows, text/image/reference conditioning,
native audio when exposed by the installed Base model, duration, resolution, seed, quantization, and
CPU offload. Capability discovery is authoritative; unavailable or cloud-only stages stay disabled.

## Quality presets

The Scene Editor exposes three named presets plus a manual Custom option. Presets are the primary
control; the explicit H3 canvas dropdown is a Custom override.

| Preset | Landscape | Portrait | Normal target | Long-shot cap | Long shot allowed |
|--------|-----------|----------|---------------|---------------|-------------------|
| Fast / Safe | 896×512 | 512×896 | 5–8 s | 20 s | yes |
| Standard | 1024×576 | 576×1024 | 5–8 s | 8 s | no |
| High | auto | auto | 5 s | 5 s | no |
| Custom | explicit canvas | explicit canvas | 1–20 s | 20 s | no |

The effective duration is rounded to the MiniMax frame grid (24 fps, step 17, offset 5). The
Scene Editor shows the effective frame count and rounded seconds while editing.
Fast / Safe uses the normal 8-second cap until the user explicitly enables Long shot; that toggle
raises only the compact preset's cap to 20 seconds. Custom requires an explicit 32-pixel-aligned
canvas and never implies that the selected duration will fit in VRAM.

Live capacity observations on a single 24 GB-class GPU: 20 s at 896×512 succeeded,
and 5 s at the Auto/1344×768 canvas is validated; longer durations at larger canvases do not fit,
so use a smaller canvas rather than expecting more headroom.

## Continuity (first-frame chaining)

H3 scenes can chain so that each shot starts from the previous scene's last frame. The chain is
configured per-scene:

- **Continue from previous H3 shot** — checkbox.
- **Predecessor scene** — dropdown of earlier H3 scenes in the same project.
- **Continuity group** — optional label; auto-assigned from the predecessor when blank.

Rules enforced by the backend:

- predecessor must be an H3 audiovisual scene with a lower index;
- predecessor and current scene must resolve to the same canvas under their respective presets;
- cycles are rejected;
- the predecessor's current visual asset must exist; otherwise the scene is `source_missing`.
- if a predecessor is regenerated, direct and transitive dependents become `source_stale`; their
  existing media remains available until the user regenerates them in order.

The director materializes continuity blocks automatically for consecutive H3 scenes in a plan.
Manual edits in the Scene Editor override the director's grouping.

## GPU/VRAM policy

On a single 24 GB-class GPU, H3 cold-load needs roughly 20 GiB of
system-wide free VRAM. The pipeline checks system-wide free VRAM before dispatch and returns a
structured `INSUFFICIENT_VRAM` error (HTTP 409) with actionable steps: release cached ComfyUI
models from Models & System Status, or unload the externally managed LLM in its router UI. Port
1234 is never touched.

The `/api/system/status` response includes `h3_readiness` so the UI can surface VRAM state before
the user requests generation. A resident H3 family can be reused without falsely requiring cold-load
headroom.

## Native H3 audio

H3 clip previews retain the native synchronized audio emitted by ComfyUI. Final Studio exports
currently keep narration and music authoritative and do not preserve the H3 clip audio. The Scene
Editor states this explicitly; preserving and mixing per-scene native audio remains a separate future
timeline feature.

## First-frame workflow

The ComfyUI workflow `workflows/comfyui/minimax-h3-av-first-frame.workflow.json` adds a LoadImage
node and a `first_frame` input on `MiniMaxH3ImageToVideo`. The pipeline extracts the predecessor's
last frame with FFmpeg, caches it in the project directory, and passes it as the first-frame image
when continuity is enabled.

## Key files

- `backend/core/h3_policy.py` — presets, canvas resolution, frame count, duration validation.
- `backend/schemas/h3_continuity.py` — graph validation and runtime status computation.
- `backend/rendering/frames.py` — atomic last-frame extraction from MP4.
- `backend/pipeline/service.py` — dispatch split (real/mock), keyframe caching, structured VRAM error.
- `backend/director/engine.py` — `continue_previous_h3` schema, H3-aware materializer.
- `backend/api/main.py` — `/api/h3/policy`, `/api/system/status` readiness, 409 mapping.
- `frontend/js/pages/scene-editor.js` — H3 preset selector, continuity controls, duration hint.
